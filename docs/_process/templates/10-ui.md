# UI

## Propósito
Levar os wireframes aprovados para alta fidelidade, com todo estado desenhado.
Tudo que é visual vem de token nomeado do design system, nunca de valor solto.

## Gate de saída
Nenhuma tela fica com estado sem desenho (vazio, erro, carregando, sucesso) e todo valor visual referencia um token do design system.
- [ ] Matriz tela versus estado preenchida, sem célula em branco.
- [ ] Célula marcada `n/a` tem uma linha dizendo por que aquele estado não existe.
- [ ] Cada estado desenhado aponta para um arquivo ou frame que abre.
- [ ] Nenhum hex, valor em px, nome de fonte ou sombra escrita à mão no documento.

## Anti-padrões
- Só a tela cheia e feliz desenhada. Vazio, erro e carregando são inventados no código, e cada dev inventa diferente.
- Hex ou px colado direto na tela porque o token não existia. O design system para de ser fonte da verdade e a próxima mudança de tema quebra a tela.
- Rótulo renomeado na UI sem voltar na fase 07. Produto, documento e código passam a usar palavras diferentes para o mesmo objeto.

## Modo reverso
Inventarie as telas em produção e preencha a matriz com os estados que o produto
realmente mostra hoje. Extraia os tokens do tema ou do CSS existente e registre pelo
nome; valor sem token vira dívida listada, nunca valor copiado para cá. Estado que
ninguém desenhou fica pendente e vira `open_question` no STATE.md, nunca suposto.
